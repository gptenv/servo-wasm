# Worker production readiness

This document tracks the 2026-09-25 review of revision `7f6bbd4a89d7f20b8350ce4b49e19714a3b52e5c`. A passing local build or test suite is evidence for the measured artifact only. The current Worker is a controlled-evaluation browser engine, not a general-purpose untrusted browsing service.

## Release profiles

| Profile | Scope | Gate |
| --- | --- | --- |
| Controlled evaluation | Single isolated runtime for trusted test pages, in-memory storage, bounded host fetches, CPU screenshots. | Local production-artifact suite and workerd fixtures. Do not promise durable data or script interruption. |
| Persistent browser service | Untrusted pages, recoverable sessions, declared supported-site corpus and durable state. | Every P0/P1 item below, green CI at the release commit, host integration and remote resource measurements. |
| Broad non-GPU compatibility | All requested non-GPU browser features. WebGL and WebGPU are excluded. | Scoped WPT and site corpus for every supported API; worker, media, storage and renderer gaps closed. |

## Review findings and disposition

| ID | Current status | Required completion evidence |
| --- | --- | --- |
| R1 execution and resources | **In progress P0.** ABI 7 adds an engine-side script work budget: the mozjs fork charges loop back-edges (weighted by loop-body size), calls, builtin loops and regexp backtracks, and terminates scripts uncatchably when a pump turn exhausts its budget (default 20M units, about 5-11 s of Node CPU). Tests cover loops, event/timer handlers, generators, async/microtask/promise storms, eval, regexp backtracking, recurring timers and runtime survival; workerd terminates a `for (;;) {}` page. Raster decoding and Worker SVG rasterization have 8 Mpixel per-image limits, but per-response caps and a storage estimate do not bound aggregate memory or temporary allocations, and the budget does not bound single long native calls. The in-memory blob store, `pushState` history-state map and page-evaluation result buffers are also unbounded. | Remote CPU calibration of the default budget; decompression/image/storage/allocation stress tests; aggregate memory limits; concurrent isolate memory and recovery measurements. |
| R2 network security | **In progress P0.** Outgoing and response cookie decisions now share a resolved client-origin rule; outgoing preexisting Cookie headers are removed before jar attachment. Non-credentialed CORS now includes Fetch preflights and simple POST bodies: the engine decides whether a preflight is needed and whether its response allows the request (the adapter only sends it), with tests asserting what the server receives for allowed and denied cases. Credentialed cross-origin fetches and complete SameSite context remain unsupported and fail closed. | Browser-differential request/response tests, redirect and cookie policy matrix, CSP/mixed-content/header audit, service-layer authentication and egress policy. |
| R3 lifecycle and isolation | **In progress P0.** Reset navigates and cancels but does not erase state or reclaim the WASM instance. Late WebSocket callbacks are now ignored after reset or socket replacement, and a new host invocation cannot start with an unread page result. | Explicit close/erase APIs, generation-safe completions across all operations, trapped-instance replacement, long-session and cross-user stress tests. |
| R4 persistent storage | **Open P1.** Storage is instance-local; `persist()` reports false and quota is unenforced. | Versioned WASM host contract; session/origin/tab-keyed DO transactions and hydration; crash/retry/migration/quota tests. The hosting integration belongs to the separate `servo-mcp` owner. |
| R5 Cache and IndexedDB | **Open P1.** Cache lifecycle and a basic IndexedDB read/write path work. | Cache request/response operations and storage accounting; IndexedDB abort, indexes, cursors, upgrade, concurrency, clone and restart tests. |
| R6 ABI | **In progress P1.** ABI 8 keeps the narrow fetch DTO introduced in ABI 6 instead of serializing internal `RequestBuilder` fields. The adapter checks the ABI and every required export (redirect cookies, script budget, correlated evaluation) at initialization; it bounds and validates host commands with malformed-message tests. | Broader state-transition fuzzing and pairwise old/new compatibility tests. |
| R7 page operations | **In progress P1.** ABI 8 adds `evaluate()`: correlated evaluation IDs, awaited promises (through Servo's internal promise reactions), structured values and errors, timeout/cancel/reset outcomes, with synchronous work bounded by the script budget. The legacy single-slot `evaluatePage()` remains. `beginInvocation()` now separates the 50-subrequest invocation counter from a 10,000-subrequest session cap; the host must call it between serialized MCP operations. | History/redirect/stream cancellation tests and host integration of the invocation boundary and `evaluate()`. |
| R8 compatibility | **In progress P1.** `worker-compatibility-matrix.md` records tested paths and known partial, unsupported and unverified areas. A trap audit of reply-bearing resource messages fixed instance-killing traps in `URL.revokeObjectURL`, `new File()`/`FormData` and `pushState` traversal, and hangs in `Blob.text()` and blob-URL fetches, by adding an in-memory blob store and history-state storage. A second probe of about 50 APIs fixed an instance-freezing hang in synchronous XHR and traps in `new Worker()` and `new AudioContext()` (they now fail explicitly); `crypto`, `FontFace`, `IntersectionObserver`, `window.print` and `execCommand` are absent. | Supported-site corpus, scoped WPT results and inventory covering workers, media, forms, streams, permissions, accessibility and renderer behavior. |
| R9 release evidence | **In progress P1.** CI now installs a pinned WASI sysroot; it records logs, the artifact, a complete Wrangler dry-run bundle and a JSON manifest with hashes, ABI, tool versions and locked Git revisions. | Green CI at exact release commit and remote CPU/memory/latency measurements. |
| R10 forks | **In progress P1/P2.** Cargo.lock records revisions; CI now emits a reachable-package license/source inventory. Fork patch/security inventories and native-path validation are incomplete. | Upstream baselines, patch owners, native tests, standard SBOM and notices for the distributed artifact. |
| R11 operations | **In progress P2.** `worker-operations.md` documents artifact identification, session retirement, trap recovery, logging boundaries and rollback. The hosting service has not implemented the prescribed telemetry or durable recovery. | Structured session/operation telemetry, expiry/deletion, rollback/schema compatibility and failure-injection tests without logging secrets. |

## Next execution order

1. Get the pinned-sysroot CI run green and retain its manifest, build log and test log. Check the complete Wrangler upload size and runtime behavior on the intended account.
2. Calibrate the engine-side script budget on the deployed platform and add aggregate memory/allocation budgets. Validate failure isolation before accepting arbitrary pages.
3. Complete cookie/CORS semantics and lifecycle cancellation, then introduce the versioned persistence bridge with the hosting-project owner.
4. Implement Cache request/response operations, broaden IndexedDB and page-operation semantics, and close the declared compatibility matrix with scoped WPT/site evidence.
5. Maintain the forks as a locked release set, add SBOM/notices and operational recovery, and run measured remote soak tests.

No routine clean build is required. Use the production profile and `cargo build --locked` with incremental caches.
